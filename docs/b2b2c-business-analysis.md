# B2B2C 多端商城业务需求分析（mall-swarm）

> 目的：为「平台端 / 商家端 / 用户端」三端业务职责重构提供依据。
> 结论先行：采用 **B2B2C 平台模式** —— 商家负责商品经营，平台负责审核与治理，用户端负责消费。
> 本文档确认后，再统一实施代码改造（分阶段验收）。

---

## 一、现状盘点与问题（改造动因）

### 1.1 三端现状

| 端 | 访问入口 | 现有页面 | 身份/接口 |
|---|---|---|---|
| 平台管理端 mall-admin-web | :8090 | 看板、商品(列表/新增/编辑/分类/品牌/类型)、订单(列表/详情/售后/原因/设置)、营销(推荐位)、系统(用户/角色)、搜索管理 | 登录 clientId=admin-app，调 `/mall-admin/*` |
| 商家端 mall-merchant-web | :8093 | 工作台、商品(Products/ProductEditor)、订单、营销 | **同样 clientId=admin-app，同样调 `/mall-admin/*`**（仅 token key 不同） |
| 用户端 H5 mall-app-web | :8088 | 首页、分类、搜索、详情、购物车、我的、订单、登录 | clientId=portal-app，调 `/mall-portal/*` |

### 1.2 后端能力

- **mall-admin**（平台服务）：product/productCategory/brand/productAttribute/productAttributeCategory/sku、order/returnApply/returnReason/orderSetting/companyAddress、coupon/couponHistory/flash/flashSession/flashProductRelation、home 推荐位(advertise/brand/newProduct/recommendProduct/recommendSubject)、subject/prefrenceArea、admin/role/menu/resource/memberLevel、minio/oss 上传
- **mall-portal**（C 端服务）：product/brand、cart、order/returnApply、sso(会员)/member/address/member/coupon/readHistory
- **mall-search**：esProduct ES 检索；**mall-auth**：/auth 按 clientId 分流登录；**mall-gateway**：统一路由/鉴权

### 1.3 核心问题

1. **身份重叠**：商家端与平台端共用同一身份（都走 admin-app 登录），两端操作的是同一份数据、同一批接口
2. **无店铺概念**：全库无 shop 实体，商品/订单不归属任何店铺，无数据隔离
3. **无审核环节**：商品创建即直接上架（publishStatus 由前端传），商家可自建自审
4. **职责错位**：平台端做了商家该做的事（建品、发货），商家端做了不该由它独占的事（与平台同权限）

## 二、各端职责清单（应有 / 不应有）

> 总原则：**平台管规则与治理，商家管经营，用户管消费。**

### 2.1 平台管理端（mall-admin-web，:8090）

| 应有业务 | 说明 | 现状 |
|---|---|---|
| 数据看板 + 待办 | 平台总览 + 待审核商品/待处理售后提醒 | 有看板，**缺待办** |
| 店铺管理 | 店铺列表、入驻审核、营业/关停 | **缺** |
| 商品审核 | 待审核队列、通过/驳回(理由)、违规强制下架 | **缺** |
| 平台基础数据 | 商品分类、品牌、属性/规格体系（商家只引用） | 有（保留） |
| 订单监管 | 全平台订单查询、售后仲裁（**不代发货**） | 有列表/详情/售后，**含发货操作→应移除** |
| 平台营销 | 首页推荐位、平台优惠券、秒杀活动 | 有（保留） |
| 会员体系 | 会员等级 | 有（保留） |
| 系统管理 | 管理员、角色、菜单、资源（动态权限） | 有（保留，扩展商家角色） |
| 搜索管理 | ES 索引重建/查询 | 有（保留） |

**不应有（从平台端移除）**：
- 替商家创建/编辑商品内容（商品内容维护移交商家端；平台仅保留审核 + 强制下架等治理动作）
- 代替商家发货（发货移交商家端；平台仅查询监管）

### 2.2 商家端（mall-merchant-web，:8093）

| 应有业务 | 说明 | 现状 |
|---|---|---|
| 工作台 | **本店**经营数据 + 待办（待发货、驳回待修改、库存预警） | 有工作台，**缺待办/店铺维度** |
| 商品管理 | 创建/编辑（含 SKU）、**提交审核**、通过后上下架、库存维护 | 有创建/编辑（**直接上架，应改为提审**） |
| 订单履约 | **本店**订单、发货（填物流） | 有（保留，加店铺过滤） |
| 店铺营销 | 店铺优惠券、店内秒杀 | 有（保留，加店铺过滤） |
| 店铺设置 | 店铺基本信息 | **缺** |

**不应有（商家端不得出现）**：
- 商品审核（不能自审）
- 平台级配置：分类/品牌/属性维护、首页推荐位、平台优惠券、会员等级、权限管理
- 其他店铺的数据（商品/订单/营销均只看本店）

### 2.3 用户端 H5（mall-app-web，:8088）

| 应有业务 | 现状 |
|---|---|
| 浏览：首页推荐、分类、搜索、商品详情(SKU/评价) | 齐全（保留） |
| 交易：购物车、确认订单、支付、订单列表/详情、确认收货、取消、退款申请 | 齐全（保留） |
| 会员：注册登录、个人中心、地址、优惠券、浏览记录 | 齐全（保留） |
| 服务：AI 客服 | 已有（保留） |

**不应有**：任何管理/运营入口（现状无，保持）。
**差距**：portal 商品查询需过滤为「审核通过 + 已上架」（审核流落地时同步）。

## 三、后端改造设计（分三阶段）

### 阶段一（P0）：商品审核闭环 + 商家独立身份 ★核心故事

1. **商家身份**：`ums_admin` 复用，加角色区分（PLATFORM_ADMIN / SHOP_MERCHANT）；登录 clientId 拆 `merchant-app`，mall-auth 按 clientId 分流，网关按角色放行接口
2. **审核状态机**：`pms_product.verify_status`（0 待审核 / 1 通过 / 2 驳回）+ 驳回理由字段
   - 商家创建/编辑 → 强制 `verify_status=0`（且不下发上架）
   - 平台审核通过 → `verify_status=1`；驳回 → `2` + 理由
   - portal 查询条件：`verify_status=1 AND publish_status=1`
3. **接口划分**：
   - merchant 角色可调：`/product/create`、`/product/update`（写入时强制 verify=0）
   - admin 角色：`/product/verify`（通过/驳回）
   - 其余接口按角色收敛
4. **前端**：
   - 商家端：商品编辑页「提交审核」、列表加审核状态列与驳回原因
   - 平台端：新增「商品审核」菜单页；商品新建入口移除（或仅自营兜底）

**验收**：商家提交 → 平台驳回 → 商家修改重提 → 通过 → 上架 → H5 可见。

### 阶段二（P1）：店铺维度数据隔离

1. 新增 `pms_shop` 表（id/name/owner/status），存量商品/订单归属默认店铺（数据迁移脚本）
2. `pms_product`、`oms_order`、营销相关表加 `shop_id`
3. 商家端接口按当前登录用户所属店铺过滤；平台端不过滤
4. 订单发货权限校验（商家只能发本店订单）；看板/工作台按店铺统计

**验收**：商家 A 看不到商家 B 的商品与订单。

### 阶段三（P2，可选）：店铺体系完善

- 店铺入驻申请 → 平台审核（复用状态机模式）
- 商家子账号、结算/对账（演示场景可进一步简化或不做）

---

## 四、实施策略与风险

- **分支开发**：`feature/b2b2c` 本地完成各阶段 → 统一构建部署（线上保持可用）
- **数据迁移**：存量数据补默认店铺/正常审核状态，避免破坏演示数据
- **分期验收**：每阶段跑通 E2E 再进下一阶段，避免大重构半途而废
- **明确取舍**：单商户 → 多租户是本项目最大改造，严格按 P0 → P1 → P2 推进；P2 可按需裁剪

## 附：现状 → 目标 差异速查

| 事项 | 现状 | 目标 |
|---|---|---|
| 商家登录身份 | clientId=admin-app（与平台相同） | 独立 merchant-app + 商家角色 |
| 商品创建后状态 | 直接上架 | verify_status=0 待审核 |
| 商品审核 | 无 | 平台端审核页（通过/驳回） |
| 平台端商品编辑 | 完整新建/编辑 | 仅审核 + 治理（强制下架） |
| 平台端发货 | 有 | 移除（移交商家端） |
| 店铺维度 | 无 | pms_shop + 数据过滤 |
| portal 商品可见性 | 上架即可见 | 审核通过 + 上架才可见 |
